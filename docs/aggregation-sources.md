# WERKS source review

Initial company target: ten candidate sources. Each candidate is assessed independently and records `compliance_status`, primary and supplementary evidence URLs, review notes/date/reviewer, redistribution and attribution permissions, allowed fields, and usage restrictions. A source is active only after a complete approved assessment; `review_required` and `blocked` sources cannot be activated or synchronized. Written permission is not a blanket prerequisite: an official API/feed license that permits WERKS's intended use is sufficient.

Jobicy is a licensed job-feed provider rather than a company source. Its current official API fair-use terms expressly allow job discovery products/job boards to use listings without individual permission; they require clear Jobicy attribution, retaining original Jobicy listing URLs, a one-request-per-second limit, and accurate unavailable/closed states. The API source is seeded active and approved with only `title`, `companyName`, `sourceUrl`, `applicationUrl`, `locationText`, `employmentType`, and `originalPostedAt` allowed. The connector only accepts listings whose location explicitly names Indonesia; APAC-wide and non-Indonesia country-specific jobs are excluded. The feed only contains listings published in the previous seven days, so stored jobs are status-checked through Jobicy's batch endpoint rather than marked closed merely because they disappear from the feed. Other fetched fields are nulled before persistence.

The career boards below are employer-branded public ATS pages. Their board identifiers are taken from those published URLs, and API endpoint patterns follow the ATS vendors' official documentation. All ten API URLs were live-checked with read-only HTTP GETs on 2026-11-19 at 14:51 WIB (HTTP 200). Counts confirm a JSON posting array only; the records were not saved. The endpoint verification timestamp is separate from permission approval.

No listed ATS company source is explicitly prohibited based on the evidence checked; those with unclear scope remain `review_required`. Explicit prohibitions should be recorded as `blocked`, and any such source must remain inactive unless the required authorization changes the assessment.
