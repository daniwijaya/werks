# WERKS ATS source compliance audit

**Reviewed:** 2026-11-20<br>
**Reviewer:** WERKS technical audit (AI-assisted)<br>
**Decision standard:** public access and robots.txt alone do not grant redistribution rights. A source remains inactive until evidence supports the intended collection and display scope.

## Findings

The provider documentation describes access to published postings, usually for the employer's own careers page or job-site integration. It does not clearly license WERKS to independently aggregate and republish those postings. The documentation also does not establish a universal attribution requirement or permitted set of display fields for third-party aggregators. Therefore, no ATS fields are approved for WERKS display yet (`allowedFields: []`), and each assessment records `redistributionAllowed: null` and `attributionRequired: null`.

All ten sources remain `review_required` and inactive. No source was marked `blocked`: the audit did not find a prohibition that clearly applies to these public job-board endpoints and WERKS's proposed limited job-discovery use. Restrictions documented for authenticated/privileged ATS APIs are not applied to the separate public endpoints without evidence that they govern them.

## Interpretation by provider

- **Greenhouse:** its public Job Board API returns published-job fields and says customers can use the data to build their own careers pages. It does not state that independent aggregators can republish the data or identify attribution/field rules. Greenhouse's separate Third-Party API Access Policy concerns customer-issued authenticated Harvest credentials and restricts using customer data to build cross-customer datasets; it does not resolve the terms for these public board endpoints.
- **Lever:** its Postings API is described as supporting a company's custom job site. Lever separately documents an XML feed for job boards and partners. That supports an employer-controlled job-board integration path, but does not establish that any third party may republish these companies' public API responses without the employer/feed being enabled for that use.
- **Ashby:** its public job posting API is documented for populating an organization's careers page, with links to Ashby's hosted posting/application pages. The docs say to omit unlisted postings from public display, but do not grant independent aggregators republication rights.

## Reassessment and activation

The Source Registry was reassessed through `reassessSources()`. The operation records the current review date, reviewer, notes, evidence URLs, usage restriction, and unresolved permission fields, and forces `isActive = false`. No existing job/source records are deleted. Activation remains a separate operation and is not performed by this audit.

Reassess an individual company if WERKS obtains a source-specific license, company authorization, or applicable terms that clearly permit defined fields and display/link behavior. Record those exact fields and attribution conditions before activating it.
