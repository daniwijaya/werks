# WERKS — Phase 5: Indonesia Source Discovery & Validation

**Checked:** 2026-11-23 (Asia/Jakarta)<br>
**Reviewer:** WERKS technical source review (AI-assisted)<br>
**Scope:** discovery, compliance evidence, technical/coverage checks, and local-only frontend fixtures. No new connector was implemented and no source was activated.

## Executive result

- The existing Jobicy API remains the only source with a clear permission assessment (`approved`, active, attribution required). Its last controlled synchronization accepted **0 Indonesia-eligible design jobs**.
- Among the 10 registered ATS company boards, the previous controlled endpoint check on 2026-11-23 found **4 title-and-location candidates** across three Greenhouse boards: Xendit 1, aCommerce 1, and DKatalis 2. Those counts use the job title classifier and an explicit Indonesia location string; they are discovery counts, not approved/public listings. No returned match explicitly stated remote eligibility for Indonesia.
- All 10 ATS sources remain `review_required` and inactive. Their public endpoints are technically useful, but provider documentation does not grant WERKS a general right to republish company postings. Greenhouse describes use for an employer’s career site; Lever describes its postings API for a company job site; Ashby says the API is for an organization’s published postings and career page. [Greenhouse Job Board API](https://docs.greenhouse.io/job-board), [Lever Postings API](https://github.com/Lever/postings-api), [Ashby Job Postings API](https://developers.ashbyhq.com/docs/public-job-posting-api).
- The best next source routes are employer-enabled feeds (SmartRecruiters’ free-aggregator publication setting and Teamtailor’s job-board integration), subject to WERKS being included/activated by the employer. Do not poll those company APIs as a substitute for that authorization.
- Local fixture tests pass for homepage cards, search-page filtering and empty results, attribution links, and Saved Jobs. Fixture code is test-only and uses `example.test` URLs. It is never imported by application code and was not written to Neon.

## Local fixture validation

The fixture is in `tests/fixtures/indonesia-design-job.ts`, labelled as test-only, uses a fake company and `.test` URLs, and has no import path from runtime code. `tests/aggregation/frontend-fixture.test.ts` renders the actual homepage feed, search page, job card, and Saved Jobs feed with the fixture injected into test mocks.

Validated behaviors:

- Homepage shows the fixture label, original listing, application link, and required source attribution.
- Search filters by query, Indonesia location, design discipline, work mode, and employment type; a non-match shows the empty state.
- Saved Jobs shows the fixture only when the test hook marks its ID as saved.
- No fixture uses Neon or appears through the production loader.

## Limitations and next actions

- ATS counts are title/location heuristics, not a human review of job descriptions; they can include false-positive design titles. Verify candidate roles on the employer page before any source-specific reassessment.
- None of the 10 ATS sources has verified field-level redistribution permission. Do not activate them.
- BJAK returned HTTP 401 for its API/robots check; do not retry around that access control.
- A repeat Node fetch from this local sandbox failed due restricted network access. The ATS count table preserves the earlier controlled 2026-11-23 response; it is not represented as freshly rechecked at report-writing time.
- Next steps are to request SmartRecruiters/Cermati aggregator inclusion and Teamtailor/Pitchday job-board opt-in, then record the exact evidence URL, fields, attribution, restrictions, review date, and reviewer through the Source Registry reassessment workflow. Keep manual JSON-LD/RSS extraction disabled unless a specific source’s terms permit it.
